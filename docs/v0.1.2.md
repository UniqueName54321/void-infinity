# v0.1.2

## Human Play

All four autoplay mods now expose **Human Play**, off by default. It uses the
existing random seed for reproducible imperfections:

- **Standard:** slower, variable reactions, smooth cursor corrections, off-centre
  circle aims, variable spinner speed, and imperfect timing.
- **Taiko:** imperfect hit timing and varied swell rhythm while retaining the
  required input types.
- **Mania:** staggered chords, varied tap lengths, and imperfect press/release timing.
- **Catch:** imperfect movement and aim, small timing errors, and occasional reach
  mistakes. Catch has binary judgements, so its accuracy cost appears as misses.

The amount of accuracy loss depends on the beatmap, difficulty, and other autoplay
settings. Human Play remains autoplay: it is not user-playable and is unavailable
in multiplayer.

A built-in autoplay icon and **AUTOPLAY · HUMAN PLAY** label appear in a compact bottom-left
badge as of v0.1.2.1, with **95% opacity**. This percentage refers to the marker's opacity,
not a target accuracy. The marker sits outside the skinning hierarchy and the
hideable HUD, has no visibility setting, and remains visible when HUD controls
are hidden. Saved autoplay settings retain the Human Play flag for replay playback.
This identifies automation within the client; it is not a claim that a modified
client or an externally edited recording can be made tamper-proof.

## Importing selected lazer content

The import panel in **Settings → Maintenance** and first-run setup now offers
independent **Beatmaps**, **Skins**, and **Options** checkboxes. Beatmaps start
selected; the other two start off. Deselect Beatmaps to import skins or options
without importing maps again. Close osu!lazer before importing.

Skins copy their assets and metadata through the normal skin importer. Deleted
and protected built-in skins are skipped. Supported skin implementations are
mapped to local types; external instantiation names are not executed.

Options import replaces supported local preferences, including menu behaviour,
background source, cursor sizing, HUD preferences, dim/blur, audio offset,
inactive volume, and editor display preferences. Unsupported values are skipped.
Accounts, tokens, online functionality, file-storage paths, foreign skin IDs,
and experimental-feature settings are not copied. Select an imported skin
manually after importing it.

The source database is opened only as a temporary, read-only snapshot for asset
imports. Options-only import reads the source settings file without opening its
database. Source files remain unchanged. Existing missing-file and database-version
limitations from v0.1.1 still apply.

## Local main-menu backgrounds

Choose **Settings → User Interface → Main Menu → Background source → Skin** to
use a custom skin's `menu-background` texture. No supporter status or login is
required. Built-in skins retain the normal background rotation. Seasonal
backgrounds retain their existing priority; disable seasonal backgrounds if you
want the skin background to remain selected throughout seasonal events.

## Experimental Features

The **Experimental Features** settings section initially shows only **Enable
Experimental Features**. Turning it on displays a warning about unfinished
features, crashes, bugs, and possible data loss. Cancelling leaves the gate off;
accepting exposes the individual switches.

Each individual switch is opt-in and does not display another warning. Currently
only **Test** exists, and it has no effect. Turning the master gate off removes
all individual switches from the list. Their saved choices are retained, but
experimental features must always honour the master gate before doing anything.
