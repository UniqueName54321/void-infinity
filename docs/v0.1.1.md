# v0.1.1

## Autoplay

Select Autoplay and open its mod customisation panel. All four modes expose a
**Timing offset** in milliseconds and a **Random seed** for repeatable choices.
The default timing offset is zero. Nonzero timing offsets, chord spreading,
hold-release offsets, or low spinner speeds can reduce accuracy or cause misses.
Autoplay remains automated, non-user-playable, and unavailable in multiplayer.

Each mode has its own controls:

| Mode | Options |
| --- | --- |
| Standard | Natural, linear, or dancing cursor paths; dance strength; adaptive, alternating, or single tapping; spinner RPM and direction; reaction time; delayed movement |
| Taiko | Alternating or preferred hand; seeded random hands; swell hit interval; extra drumroll hits |
| Mania | Ordinary-note tap duration; seeded chord spread; long-note release offset |
| Catch | Catcher aim offset; seeded aim variation; early movement; always dash |

Cursor dance changes travel between objects while retaining exact click
positions and slider following. Overlapping standard objects still alternate
buttons where necessary. Taiko strong notes retain both-hand hits, and swell
input accelerates when needed to meet its required hit count. Mania releases
ordinary notes before the next note in the same column. Catch aim variation
stays within the catcher's usable width. Existing autoplay defaults remain the
baseline when the new controls are left alone.

## Import an osu!lazer library

Open **Settings → Maintenance → Import osu!lazer library**, or use the
**Import from osu!lazer** step in first-run setup.

1. Close osu!lazer so its database and assets remain consistent during copying.
2. Paste the lazer data folder's full path or use **Choose folder…**. Select the
   folder containing both `client.realm` and `files`, not the application binary
   or an individual hashed asset directory.
3. Press **Import beatmaps from osu!lazer**. Progress reports each set. Cancelling
   stops between operations and keeps sets already imported.

The importer copies beatmaps and associated assets; it does not transfer accounts,
scores, collections, or application settings. Deleted sets are skipped. Missing
assets cause that set to fail rather than importing an incomplete copy. Existing
sets are handled by the normal duplicate detection. Allow enough disk space for
copied assets, a database snapshot, and one temporary beatmap archive at a time.

The source database is copied through a read-only file handle. Only the temporary
snapshot is opened with Realm, using a dynamic, read-only schema; the source is
never migrated. The source database's size and modification time are checked
around copying. Filenames and content hashes are validated before assembling
archives, and online metadata lookup is disabled for this import path.

A database written by an unsupported Realm storage-engine version may still fail
to open. In that case, export beatmap archives from lazer and use normal file
import. Importing the current void!infinity data folder into itself is rejected.
