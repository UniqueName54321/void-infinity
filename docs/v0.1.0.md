# v0.1.0 — The (mostly) Slider Update

## Editing sliders

Select a slider, right-click a control point, and choose **Change velocity**.
Enter a positive multiplier and press **Accept**. Each point defaults to `1`.
Velocities interpolate linearly between control points, using their cumulative
control-polygon distance to place them along the slider. Timing integrates the
whole profile: changing velocity changes duration, tick times, ball movement,
reverse spans, and conversion to a stream together. The input accepts values in
`(0, 100]` and rejects NaN and infinity.

Choose **Add movement** to drag a point to its destination, then press **Accept**.
**Cancel** restores its previous movement; **Remove movement** clears it.
The base control point stays in place. During playback, its displacement grows
linearly from zero at the slider's start to the destination at its end, including
all repeats. Scrubbing backwards evaluates the same animation without changing
the authored map. Trimmed sliders retain their original trim fraction.

Movement defaults to a 64px radius. The dotted circle shows that boundary; turn
**Clamp slider control point movement** off in **Setup → Difficulty** to remove
it for subsequent movement edits. Converting a moving slider into a stream asks
for confirmation and creates stationary circles along its original path, using
its velocity profile. Undo restores the slider and its movement.

## Events

The **Event** composition tool places an editor marker. Select it and click
**Edit event** in the Inspector to choose its type and settings. The available
type is **Change attributes**.

Supported attributes are circle size, approach rate, overall difficulty, HP
drain, slider multiplier, and slider tick rate. Blank values leave the current
setting alone. Changes persist until overridden by a later event. Difficulty
values accept `0–10`; slider multiplier and tick rate accept `(0, 100]`.

Object settings use the attributes effective at the object's start time; existing
objects finish with their original settings. HP drain also changes over time.
Events have no gameplay graphic, input requirement, hitsound, score, combo,
stacking, or aim-difficulty contribution. Event editing and attribute playback
are implemented for the standard ruleset. Other ruleset conversions omit Events
rather than turning them into notes.

## Native files

Saving in the editor writes `.vib`. Normal beatmap export creates a `.vibz` ZIP
archive containing beatmaps and their associated assets. Existing `.osu`, `.osz`,
and `.olz` imports remain supported, alongside `.vib` and `.vibz` imports.
A standalone `.vib` contains the map; use `.vibz` to share its audio and assets.

Version 1 of `.vib` starts with `void!infinity beatmap v1`, followed by JSON.
It contains a legacy-compatible beatmap payload plus exact path control points,
velocity/movement data, Events, and the movement-clamping preference. Storyboards
and beatmap colours read the embedded payload too. No CLR type names are used in
the native extension data.

Undo/redo uses the native representation to retain the new features. Legacy
export rejects native `.vib` beatmaps and directs you to `.vibz`, preventing
silent loss of their features. Saving changes a difficulty's stored file within
its existing local beatmap set; this is not a bulk migration of your library.
